# FrameBurst 1.3.0

FrameBurst now works on PCs whose graphics hardware can't run its Direct3D 11 capture path.

## Download

**[FrameBurst-Setup-1.3.0.exe](https://github.com/LunoviaVR/FrameBurst/releases/download/v1.3.0/FrameBurst-Setup-1.3.0.exe)**:
run it and follow the steps. If you already have FrameBurst installed, open **Settings › About** and choose
**Check for updates**. Your settings are kept.

**Requirements:** Windows 10 version 2004 or later, or Windows 11 (64-bit). A Direct3D 11 GPU is recommended.

## New
- **GDI fallback capture.** If no GPU supports Direct3D 11 (feature level 11.0), the system is running on the
  Microsoft Basic Display Adapter, or Windows Graphics Capture isn't available, FrameBurst now captures with
  GDI `BitBlt` instead of failing. It switches automatically and stays on GDI for the rest of the session.
- If a GPU capture fails for any other reason, FrameBurst retries that capture once with GDI before showing
  an error.
- The capture notification shows **GDI** instead of the GPU name when the fallback was used, and the switch
  is recorded in `%APPDATA%\FrameBurst\frameburst.log`.

## Good to know
- GDI capture is slower. It copies each monitor through the CPU, so on large multi-monitor setups expect
  noticeably longer capture times than the ~45 ms GPU path.
- With GDI, monitors are copied one after another rather than at the same instant, captures are 8-bit SDR
  only (no HDR copy), and some hardware-accelerated or full-screen content may come out black.
- PCs with a working Direct3D 11 GPU behave exactly as before.
